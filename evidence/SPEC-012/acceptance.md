# SPEC-012 — critères d'acceptation

Tous les résultats ci-dessous proviennent de l'exécution réelle du 2026-11-11 (horloge figée
`2026-11-11T12:20:00Z`, `LLM_MODE=mock`) sur Docker Engine 29.9.3 et Docker Compose v5.7.1.
Les rapports complets sont dans `unit.json`, `integration.json`, `e2e.json`, `checks.json` et les
artefacts de construction dans `build-web.txt`, `build-worker.txt`, `compose-config.txt`,
`health.json`, `stack.json`, `volumes.txt`.

- ✅ **CA-1** — preuve : `integration.json`, test « construit deux images non root, sans fichier .env et avec le même commit » : `docker build` réel de `learny-selfhost-it-<pid>-web:test` et `-worker:test` depuis `docker/web.Dockerfile` et `docker/worker.Dockerfile` (`build-web.txt`, `build-worker.txt`), étiquettes `org.opencontainers.image.revision=dc30f2d` et `version=0.0.0-spec-012` identiques sur les deux images ; `docker run --entrypoint sh … id -u` renvoie `1000` (utilisateur `node`) pour les deux ; `find / -name ".env*"` est vide et les variables d'image ne contiennent ni `SUPABASE_SERVICE_ROLE_KEY`, ni `APP_ENCRYPTION_KEY`, ni `POSTGRES_PASSWORD`. Le test « démarre la pile déclarée et répond aux sondes réelles (sans Mailpit) » obtient `stackReady=true` pour les 9 services et `health.json` montre `web /api/v1/health` HTTP 200 (`commit=dc30f2d`), `worker /health` `ok`, `postgres pg_isready` `accepting connections`, `inngest /health` code 0. Les deux images démarrent réellement sous utilisateur non root et répondent à leur santé.

- ✅ **CA-2** — preuve : `integration.json`, test « un redémarrage conserve la base, le stockage et les migrations » : un enregistrement de test `probe-<pid>` est écrit dans `public.selfhost_probe`, relu après `docker compose restart db` (valeur identique), puis après `docker compose down` (sans suppression de volumes) et `up -d`. L'identifiant du volume de test est consigné dans `volumes.txt` : `learny-selfhost-it-<pid>_db-data`, `…_storage-data`, `…_inngest-data`. Le fichier `/var/lib/storage/selfhost-probe.txt` est retrouvé après le cycle arrêt/redémarrage, et `applied_at` de la migration `0000_extensions.sql` reste inchangé (aucune migration destructive rejouée). `stack.json` et `health.json` attestent la pile démarrée par Compose.

- ✅ **CA-3** — preuve : `unit.json`, tests « refuse une variable obligatoire absente et documente la syntaxe :? », « Dockerfiles : lockfile gelé, multi-étapes, non root, sans fichier .env » et « .dockerignore exclut secrets, dépendances et historique Git » : les 12 variables obligatoires sont déclarées en `${VAR:?…}` et une valeur vide est refusée. `integration.json`, test « un secret obligatoire absent empêche la configuration (CL-1, CA-3) » : `docker compose config` échoue avec `POSTGRES_PASSWORD` comme variable manquante, et le message ne contient pas la valeur du secret. `compose-config.txt` est la configuration résolue réellement obtenue, avec toutes les valeurs sensibles remplacées par `***` ; aucun fichier `.env` n'existe dans les images (scan `find`) et les `ARG` de build ne contiennent aucun secret (seuls les `NEXT_PUBLIC_*` publics sont acceptés). Aucune preuve ni image ne contient de secret.

- ✅ **CA-4** — preuve : `unit.json`, test « le guide couvre démarrage, migrations, sauvegarde, mise à jour et arrêt » : `docs/operations/self-hosting.md` contient les sections prérequis, secrets, démarrage, migrations, santé, sauvegarde, mise à jour coordonnée et arrêt sans suppression de volume, ainsi que les références `docker/compose.selfhost.yml`, `.env.selfhost` et `tools/docker/check-selfhost.mjs`. Le document décrit la copie de `.env.example` vers `.env.selfhost`, la génération des secrets, l'application idempotente des migrations, la sauvegarde `pg_dump` + volume Storage, la mise à jour des images applicatives et tierces épinglées, et l'arrêt par `down` sans option de suppression des volumes. L'intégration réelle exécute ces mêmes commandes de configuration, démarrage, santé et arrêt.

- ✅ **CA-5** — preuve : `e2e.json` et `video/` : test « inspecte la pile auto-hébergée @SPEC-012 » (titre `h1` « Auto-hébergement », chaînes « Web → Supabase / Inngest » et « Worker → Inngest », 9 composants Compose, 9 images avec version/commit, 8 sondes, commandes `config`, `up -d --build`, `check-selfhost`, `down`), test `@visual` « auto-hébergement conforme @SPEC-012 » : ordre des quatre régions `spec-012-services`, `spec-012-images`, `spec-012-health`, `spec-012-commands`, jetons de bordure/rayon, axe sans violation serious/critical (`attachments/*axe.json`), captures desktop 1440×900 et mobile 390×844 comparées à ≤ 1 % (`apps/web/e2e/__screenshots__/p0/spec-012.spec.ts/`, `screenshots/`), et 5 vidéos conservées. La page ne lance pas Docker et n'affiche aucune variable d'environnement : elle lit uniquement le relevé public `selfhost-check.json` ou affiche « Non vérifié » ; en mode démonstration, l'état simulé est explicitement étiqueté `Démonstration`.
