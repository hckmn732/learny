# SPEC-510 — Critères d'acceptation

- ✅ CA-1 — Une page publique de fixture produit titre, texte principal et ancrages, puis des passages citables sans contenu de navigation parasite. Preuves : tests unitaires `packages/ingestion/src/extract/remote.test.ts` « extrait le titre… », « conserve des passages exacts… » ; test d'intégration `packages/ingestion/test/integration/remote.test.ts` « traite une page… » ; e2e `spec-510.spec.ts` ; `unit.json`, `integration.json`, `e2e.json`.
- ✅ CA-2 — Une vidéo de fixture produit des segments horodatés et une vidéo sans sous-titres produit `NO_CAPTIONS`. Preuves : unitaire « extrait des segments YouTube… » ; intégration « refuse … une vidéo sans sous-titres » ; e2e onglet YouTube ; `unit.json`, `integration.json`, `e2e.json`.
- ✅ CA-3 — URL privée directe ou après redirection, robots refusé, dépassement de 15 s ou 5 Mo sont bloqués avec le code attendu. Preuves : `packages/core/src/net/safe-fetch.test.ts` (URL_BLOCKED_HOST, WEB_ROBOTS_DISALLOWED, FETCH_TIMEOUT, FETCH_TOO_LARGE, FETCH_TOO_MANY_REDIRECTS) ; unitaire « traduit un refus robots.txt » ; intégration « refuse une adresse privée » ; `unit.json`, `integration.json`.
- ✅ CA-4 — Une image traitée en `LLM_MODE=mock` produit un passage marqué comme lecture IA, stable à répétition, sans appel réel. Preuves : unitaire « lit une image par le modèle light… » ; intégration « lit la même image deux fois… » (même texte, `contentOrigin=model`, ancre `lecture-ia`, modèle simulé) ; `integration.json`.
- ✅ CA-5 — La démonstration compare les trois types et erreurs, avec vidéo, axe et `@visual`. Preuves : e2e filmé `apps/web/e2e/specs/p5/spec-510.spec.ts` (2 tests) ; axe sans violation serious/critical ; test `@visual` desktop et mobile ; `evidence/SPEC-510/video/`, `screenshots/`, `visual/`, ligne de base `apps/web/e2e/__screenshots__/p5/spec-510.spec.ts/`.
