## Critères

- ✅ CA-1 — Créer un groupe produit un code `LRN-XXXX` et dix places ; deux adhésions concurrentes ne dépassent jamais la borne. Preuves : `unit.json` (`CA-1 — créer un groupe produit un code LRN-XXXX et dix places`, `CA-4 — la onzième place répond groupe complet`), `integration.json` (`CA-1 — crée un code LRN-XXXX, dix places et refuse un second groupe`, `CA-1, CL-4 — deux adhésions simultanées au dixième siège : une seule réussit` avec exactement 10 lignes `group_members` actives), e2e `parcours SPEC-724 @SPEC-724` qui crée le groupe depuis l’interface et vérifie le motif du code (vidéo `video/03-parcours-spec-724-desktop.webm`).
- ✅ CA-2 — Un membre ne voit que les quatre champs publics d’un autre membre ; la lecture directe de ses apports, cours et lacunes répond 404/RLS. Preuves : `unit.json` (`CA-2 — la projection ne contient que les quatre faits publics` vérifie la liste exacte des clés), `integration.json` (`CA-2 — la page ne montre que les quatre faits publics et la RLS cache le reste` : un apport privé du propriétaire renvoie 0 ligne sous le JWT du membre, l’extérieur reçoit `NOT_FOUND`, la page ne contient ni adresse e-mail ni contenu privé), e2e `parcours SPEC-724 @SPEC-724` (aucune adresse e-mail ni contenu privé dans la page Groupe).
- ✅ CA-3 — Quitter crée une formation individuelle avec les résultats privés conservés ; l’ancien code régénéré n’accepte plus de nouveau membre. Preuves : `unit.json` (`CA-3 — quitter renvoie la nouvelle formation individuelle`, `CA-3 — la copie individuelle recopie le programme et déplace les données privées`, `CA-3 — régénérer le code invalide l’ancien et le propriétaire seul peut le faire`), `integration.json` (`CA-3, CA-4 — quitter conserve les résultats privés, retire le membre et invalide l’ancien code` : nouvelle formation avec `group_id` nul, deux `module_progress` déplacés dont un validé, apport déplacé, `left_at` renseigné, ancien code en `NOT_FOUND`), e2e `parcours SPEC-724 @SPEC-724` qui quitte depuis l’interface puis ouvre la nouvelle formation individuelle.
- ✅ CA-4 — Un second utilisateur reçoit 404 pour les données du premier ; deux requêtes identiques ne dupliquent ni écriture ni événement, et une requête invalide ne crée rien. Preuves : `unit.json` (`CA-4 — une entrée invalide ne lance aucune écriture`, `CA-4 — un groupe d’un autre apprenant est un 404 sans fuite`, `CA-4 — une adhésion déjà active ne réécrit rien et n’émet aucun second événement`, `CA-4 — une quatrième formation active refuse l’adhésion`), `integration.json` (`CA-4 — invalide, non-propriétaire et double envoi ne produisent qu’un effet` : une seule ligne `group_members`, un seul `event_outbox` avec l’identifiant stable, `NOT_FOUND` pour l’intrus, `FORMATION_LIMIT_REACHED` à la quatrième formation). Les routes portent `Idempotency-Key` (contrats vérifiés par `unit.json`).
- ✅ CA-5 — La démonstration suit les jetons et la structure prescrits ; axe ne signale aucune violation serious/critical, les captures desktop/mobile restent ≤ 1 % et une vidéo e2e est conservée. Preuves : e2e `conformité SCR-17 groupe desktop @SPEC-724 @visual` et `conformité SCR-17 groupe mobile @SPEC-724 @visual @mobile` réussis avec baselines `spec-724-groupe-desktop-desktop-linux.png` et `spec-724-groupe-mobile-mobile-linux.png` (seuil de 1 %), jetons vérifiés (`group-code` fond `#F4F4F1`, cartes `#FFFFFF` rayon 21,6 px, bordure `#E7E6E1`), captures `visual/06-…desktop…png` et `visual/15-…mobile…png`, axe sans violation serious/critical (`attachments/01`, `attachments/06`, `attachments/14`), vidéo `video/03-parcours-spec-724-desktop.webm`.
